# 1교시 — Project, 우리 회사를 아는 전략 참모

**시간** 14:00–15:00 (실습 14:30–15:00)

**목표** 회사 지식과 지침을 한 번 넣어 두고, 매번 설명하지 않아도 우리 회사 기준으로 답하는 참모를 만든다.

!!! success "이 교시의 결과물"
    - ① Project '전략 참모, [우리 회사]' (지식 파일 + 지침)
    - ② Project 안, 밖 비교 메모

### 1-1. 지식 파일 준비, 회사 개요 1장 만들기

Project 지식은 '회사 사실의 기준'이 됩니다. 길고 많은 파일보다 정리된 짧은 파일이 낫습니다.

!!! abstract "경로"
    Cowork (AI전략기획실 폴더 연결) › 새 작업

1. 완성 파일과 함께 아래 파일을 지식으로 쓸 준비를 합니다.

**입력, 그대로 복사해 [대괄호]만 바꿔 넣으세요**

```text
00_회사자료의 사업보고서와 KPI 파일을 읽고 Project 지식용 '회사개요_1장'을 만들어줘.
구성: 회사 한 줄 소개, 사업별 매출 비중, 지역별 매출 비중, 주요 고객과 비중, 생산 거점, 원가 구조(큰 항목 3개), 올해 KPI 목표, 지금의 핵심 이슈 5개.
모든 숫자에 출처 파일명을 달고, 표 위주로 2쪽 이내. Word로 00_회사자료에 저장해줘.
```

!!! success "기대 결과"
    00_회사자료/회사개요_1장.docx

!!! tip "팁"
    지식으로 넣을 파일: 회사개요_1장, KPI 파일, 사업 포트폴리오 자료, 4회차 산출물 3개(경쟁사동향_1장_v2, 산업통상_리스크진단, 핵심과제123_정의서)

### 1-2. Project 만들기

!!! abstract "경로"
    왼쪽 메뉴 › Projects › + New project (화면 확인)

1. 이름: 전략 참모, [우리 회사]
2. 설명: [우리 회사] 경영 판단을 돕는 전략 참모. 회사 지식과 4회차 진단 결과를 기준으로 답한다.
3. 만들기를 누릅니다.

!!! tip "팁"
    Cowork에도 Project가 있습니다(지침, 예약 작업, 로컬 폴더, 메모리를 묶음). 화면에 따라 Cowork Project에서 이 Project를 '맥락'으로 연결할 수 있습니다 (화면 확인).

### 1-3. 지식 올리기

!!! abstract "경로"
    Project 화면 › 지식(Knowledge) › + 파일 추가 (화면 확인)

1. 1-1에서 정한 파일 5~7개를 올립니다.
2. 올린 파일 목록에 모두 보이는지 확인합니다.

!!! warning "주의"
    - Project 안의 대화끼리는 서로의 내용을 모릅니다. 공유되는 것은 지식에 올린 파일과 지침뿐입니다.
    - 민감 자료는 올리지 않습니다. 회사 계정에서 Project를 공유하면 보기, 편집 권한자가 지식을 볼 수 있습니다.

### 1-4. 지침 넣기, 전략 참모

지침은 이 Project 안의 모든 대화에 적용되는 '일하는 방식'입니다. 역할, 형식, 기준, 금지, 먼저 질문, 다섯 줄이면 충분합니다. 들여쓴 줄은 우리 회사에 맞게 채우는 보충 설명입니다.

!!! abstract "경로"
    Project 화면 › 지침(Instructions) › 편집 (화면 확인)

**입력, 그대로 복사해 [대괄호]만 바꿔 넣으세요**

```text
[역할] 너는 [우리 회사] [내 직책]의 전략 참모야. 모든 답은 지식에 있는 회사 KPI와 핵심 과제 1-2-3을 기준으로 판단해.
  - 우리 회사: [업종, 주요 제품, 매출 규모, 주요 고객]
  - 올해 핵심 목표: [KPI 1], [KPI 2], [KPI 3]
  - 지식에 올린 파일이 회사 사실의 기준이야. 웹 정보와 다르면 둘 다 보여주고 차이를 표시해.

[형식] 결론부터 말해(BLUF). 맨 위 한 줄 결론 → 근거 3개 → 우리 회사 영향 → 권고 액션 순서.
  - 권고 액션에는 담당 조직과 기한을 붙여. 한 화면 안에 끝내고, 길어지면 요약을 먼저 둬.

[기준] 영향은 매출, 원가, 고객, 공급망 네 가지로 나눠 보고(파급효과 매트릭스), 숫자에는 출처와 기준일을 달아.
  - 가능하면 영향 범위(최소~최대)와 계산 근거를 보여줘.
  - 사실, 추정, 의견을 구분해 표시하고, 듣기 좋은 말보다 불편한 사실을 먼저 말해.

[금지] 출처 없는 숫자, 우리 회사와 무관한 일반론, 확인 안 된 내용을 사실처럼 쓰기.
  - 보내기, 삭제, 공유처럼 되돌릴 수 없는 일을 내 승인 없이 실행하기.

[먼저 질문] 질문이 애매하면 답하기 전에 무엇을 위한 것인지 먼저 물어봐. 질문은 최대 3개까지.
```

!!! example "예시, (주)한빛정밀 (가상 회사)"
    - [업종] 자동차 제동, 섀시, 전동화 부품, 매출 1조 2,400억 원, 주요 고객 국내 A사 41%
    - [KPI] 영업이익률 5.5%, 전동화 매출 비중 30%, 고객 상위 1개사 비중 38%

### 1-5. 메모리 설정

!!! abstract "경로"
    Settings › Memory

1. 메모리를 켭니다. 회사 계정은 관리자가 허용해야 메뉴가 보입니다 (화면 확인).
2. 메모리는 Project별로 따로 저장됩니다. 이 Project의 메모리는 다른 Project에 섞이지 않습니다.
3. 지난 대화 검색 기능도 함께 켤 수 있으면 켭니다 (화면 확인).

!!! tip "팁"
    메모리가 안 켜져도 실습은 됩니다. 지식과 지침이 핵심입니다.

### 1-6. 같은 질문, Project 안과 밖 비교

회사 이야기가 필요한 질문을 골라야 차이가 잘 보입니다.

1. Project 밖(일반 새 대화)에서 아래 질문을 먼저 입력합니다.
2. Project 안 새 대화에서 똑같이 입력합니다.
3. 두 답을 나란히 놓고 아래 비교표를 채운 뒤, 달라진 점 3가지를 메모합니다.

**입력, 그대로 복사해 [대괄호]만 바꿔 넣으세요**

```text
[우리 회사의 가장 큰 이슈, 예: 미국 관세]가 우리에게 어떤 의미야? 내가 이번 주에 할 일도 하나 알려줘.
```

| 비교 항목 | Project 밖 | Project 안 |
| --- | --- | --- |
| 우리 회사 수치를 인용했나 |  |  |
| 첫 줄이 결론(BLUF)인가 |  |  |
| 먼저 질문을 했나 |  |  |
| 담당, 기한이 있나 |  |  |
| 바로 보고에 쓸 수 있나 (1~5점) |  |  |

### 1-7. 지침 한 줄 다듬기

1. 제안받은 한 줄을 지침 맨 아래에 직접 붙여 넣고 저장합니다.

**입력, 그대로 복사해 [대괄호]만 바꿔 넣으세요**

```text
방금 답에서 [마음에 안 드는 점, 예: 근거가 너무 길다]가 아쉬워. 이 Project 지침에 넣을 한 줄 규칙을 제안해줘.
```

## 결과물 체크

- [ ] Project '전략 참모, [우리 회사]'가 있다
- [ ] 지식 파일 5개 이상이 올라가 있다
- [ ] 지침(역할, BLUF, 기준, 먼저 질문)이 저장돼 있다
- [ ] 안, 밖 비교표를 채웠다

!!! abstract "저장"
    Project 안 (파일 저장 없음), 회사개요_1장은 00_회사자료
