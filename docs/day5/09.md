# 부록 2 — 베스트 프랙티스 요약

Anthropic 공식 프롬프트 가이드(platform.claude.com)에서 임원 업무에 바로 쓰는 것만 골랐습니다.

| 원칙 | 이렇게 쓴다 | 예 |
| --- | --- | --- |
| 맥락을 모르는 유능한 신입 | 맥락 없는 동료가 헷갈려할 지시라면 Claude도 헷갈린다. 목적과 이유를 같이 준다. | "이사회 보고용이야. 관세가 가장 큰 걱정이라서 그 부분을 깊게." |
| 위임 지시서 5요소 | 목표, 맥락, 자료, 기준, 형식을 빠짐없이 쓴다. | [목표] … [맥락] … [자료] … [기준] … [형식] … |
| 자료는 위, 질문은 아래 | 긴 자료를 먼저 주고 질문은 맨 마지막에. 복잡한 입력에서 최대 30% 향상. | 파일 목록 → 읽을 범위 → 마지막 줄에 질문 |
| 인용 먼저 | 분석 전에 관련 문장, 숫자를 출처와 함께 먼저 뽑게 한다. | "관련 문장을 파일명과 함께 먼저 뽑고, 그다음 분석해줘" |
| 교차 확인, 경쟁 가설, 확신도 | 좋은 답의 기준을 말하고, 출처끼리 맞춰 보게 하고, 해석을 2~3개 내게 한 뒤 확신도를 붙이게 한다. | "숫자는 두 곳 이상에서 확인. 가설 2~3개와 각각의 확신도(높음, 중간, 낮음)" |
| 되돌릴 수 없는 일은 승인 | 보내기, 삭제, 공유처럼 남에게 보이거나 되돌리기 어려운 일은 실행 전에 묻게 한다. | "메일은 초안만 만들고 보내지 마" |
| 어려운 문제는 깊게 | 중요한 판단은 더 깊이 검토해 달라고 명시한다. | "결론 내기 전에 반대 근거까지 충분히 검토해줘" |
| 예시를 보여준다 | 형식을 맞추는 가장 확실한 방법. 실제와 비슷하고 서로 다른 예시 3~5개. | "지난달 경영회의 보고서를 첨부할게. 이 구성과 분량으로 써줘" |
| '하지 마' 대신 '이렇게' | 하지 말 것보다 원하는 모습을 말한다. 원하는 수준도 직접 말한다. | "길게 쓰지 마" 대신 "세 줄 요약 + 표 하나, 이사회에 바로 올릴 수준으로" |
| 칸을 나눈다 | 목표, 자료, 기준처럼 구역을 표시하면 섞이지 않는다 (공식 가이드의 XML 태그). | [목표] … [자료] … 또는 &lt;자료&gt; … &lt;/자료&gt; |
| 초안, 검토, 고치기 | 초안을 받으면 기준을 주고 스스로 검토해서 고치게 한다. | "이 기준으로 네 초안을 검토하고 고쳐줘" |
| "먼저 물어봐" (실전 팁) | 공식 문서에는 없지만 효과가 크다. 지시 마지막 줄에 붙인다. | "시작 전에 궁금한 점이 있으면 먼저 물어봐" |

!!! note "한 번 잘된 일은 스킬로"
    - 같은 지시를 세 번째 쓰고 있다면 스킬로 만들 때입니다. "방금 한 방식을 스킬로 만들어줘" 한 줄이면 됩니다.
    - 스킬로 만들 일 고르는 3가지 질문: ① 반복되는가 ② 우리만의 기준이 있는가 ③ 사람마다 품질이 다른가
